# Memory Site — офлайн scrapbook-книга воспоминаний

Сайт выглядит как физическая книга: бумажные страницы, стопки снимков, свободные коллажи, рукописные подписи, видео и Live Photos. Финальная версия не требует домена, сервера или интернета: всю папку можно положить на флешку и открыть через `index.html`.

## Главный сценарий для большого архива

Для 800–900 файлов не нужно вручную прописывать каждую фотографию.

1. В приложении **Фото** на Mac выдели нужные материалы.
2. Выбери **Файл → Экспортировать → Экспортировать неизменённые оригиналы**. Это важно для HEIC, исходных дат и пары HEIC+MOV у Live Photo.
3. Сохрани экспорт в отдельную папку вне репозитория.
4. Один раз установи инструменты:

```bash
zsh tools/setup_mac.sh
```

5. Активируй окружение и запусти импорт:

```bash
source .memory-venv/bin/activate
python3 tools/import_memories.py "/путь/к/папке/экспорта"
```

6. Открой `tools/studio.html`, поправь ошибочные группы перетаскиванием и нажми **«Экспортировать memories.js»**.
7. Замени экспортированным файлом `content/memories.js`.
8. Открой `index.html` и проверь книгу.

## Что делает автоматический импортёр

`tools/import_memories.py` работает локально и ничего не отправляет в сеть. Он:

- читает EXIF и QuickTime-даты;
- использует GPS, когда он присутствует;
- конвертирует HEIC/HEIF в совместимые JPEG-копии;
- создаёт лёгкие превью отдельно от полноразмерных кадров;
- транскодирует обычные видео в MP4/H.264;
- связывает пары Live Photo по Apple `ContentIdentifier`, а при его отсутствии — по имени файла и времени;
- сортирует всё по времени;
- создаёт первичные события по временным разрывам;
- дополнительно учитывает расстояние между GPS-точками;
- использует средний цвет и perceptual hash как вспомогательный визуальный сигнал;
- создаёт резервную копию предыдущего `content/memories.js`.

Визуальная близость **может быть прокси одного места или события, но не является точным распознаванием сюжета**. Поэтому после импорта предусмотрена ручная корректировка.

### Настройка чувствительности

```bash
python3 tools/import_memories.py "/путь/к/экспорту" \
  --gap-minutes 75 \
  --merge-gap-minutes 180 \
  --visual-threshold 0.72
```

- `--gap-minutes` — обычный допустимый разрыв внутри события;
- `--merge-gap-minutes` — большой разрыв, который разрешается только для очень близкого места и похожей сцены;
- `--visual-threshold` — порог визуального сходства от `0` до `1`.

Сначала можно проверить импорт на небольшой выборке:

```bash
python3 tools/import_memories.py "/путь/к/экспорту" --limit 100
```

## Почему финальный сайт не читает HEIC напрямую

Safari умеет работать с HEIC, но поддержка формата между браузерами и системами неравномерна. Для подарочной флешки надёжнее хранить исходники отдельно, а сайту отдавать подготовленные JPEG. То же относится к iPhone-видео: MP4/H.264 открывается стабильнее, чем исходный MOV/HEVC.

Финальный сайт остаётся простым статическим набором файлов и открывается через `file:///.../index.html`.

## Live Photos

Live Photo состоит из фотографии и короткого MOV. Импортёр связывает их и создаёт:

- статичную JPEG-фотографию для страницы;
- короткий MP4-фрагмент движения;
- отметку `LIVE`;
- кнопку **«Оживить фото»** в полноэкранном просмотре.

Исходную пару HEIC+MOV лучше дополнительно хранить в отдельной папке `ORIGINALS` на флешке.

## Ручная корректировка в Memory Studio

Открой:

```text
tools/studio.html
```

Редактор позволяет:

- перетаскивать фото и видео между событиями;
- создавать пустые события;
- объединять событие с предыдущим;
- менять порядок событий;
- редактировать название и общую подпись события;
- редактировать подпись каждого файла;
- удалять лишние элементы из книги;
- сохранять локальный черновик;
- экспортировать готовый `memories.js`.

Редактор не изменяет исходные фотографии. Он работает только со структурой книги.

`media/generated` и исходный экспорт не следует коммитить в GitHub: сотни фотографий быстро раздуют репозиторий. Они должны лежать в локальной рабочей папке и затем на флешке.

## Автоматически созданный блок события

Импортёр создаёт блоки такого вида:

```js
{
  type: "event",
  id: "event-2024-014",
  title: "12 августа 2024",
  caption: "Добавь сюда одну короткую деталь об этом дне.",
  layout: "collage",
  items: [
    {
      kind: "live",
      src: "media/generated/photos/abc.jpg",
      thumb: "media/generated/thumbs/abc.jpg",
      liveVideo: "media/generated/live/abc.mp4",
      caption: "12 августа 2024, 18:42"
    },
    {
      kind: "video",
      src: "media/generated/videos/def.mp4",
      poster: "media/generated/posters/def.jpg",
      caption: "12 августа 2024, 18:45"
    }
  ]
}
```

Книга показывает событие как небрежно разложенный набор кадров. По нажатию открывается вся последовательность.

## Ручные главы и блоки

Старые ручные блоки продолжают работать:

- `photo`;
- `stack`;
- `collage`;
- `video`;
- `audio`;
- `note`;
- `quote`;
- `caption`;
- `letter`.

Для небольших особых глав можно использовать `tools/editor.html` и вручную дописывать `content/memories.js`.

## Подготовка флешки

1. Формат — `exFAT`, чтобы её читали macOS и Windows.
2. Скопируй всю папку проекта вместе с `media/generated`.
3. При желании переименуй `index.html` в `ОТКРОЙ_МЕНЯ.html`.
4. Добавь рядом отдельную папку `ORIGINALS` с исходными HEIC/MOV.
5. Проверь сайт непосредственно с флешки минимум в Safari и Chrome.
6. Не загружай приватный архив на публичный хостинг.

## Ограничения

- Алгоритм не понимает смысл отношений или содержание фотографии; он группирует по техническим признакам.
- Средний цвет может ошибочно объединять разные тёмные помещения, небо, снег или кадры с похожим освещением.
- Старые файлы без EXIF могут получить дату изменения файла.
- Некоторые отредактированные или повторно экспортированные Live Photos теряют идентификатор пары; в таком случае используется совпадение имени и времени.
- Подписи автоматически создаются из даты и времени. Человеческие подписи к важным событиям всё равно лучше добавить вручную.
