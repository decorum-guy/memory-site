# Как собрать и закончить Memory Site

Это инструкция для Артёма: от экспорта фотографий из Apple Photos до финальной проверки сайта на флешке.

## 0. Как устроен проект

У проекта четыре независимые части:

1. **Исходники** — оригинальные HEIC/JPG/MOV/MP4, экспортированные из приложения «Фото». Они не изменяются.
2. **Импортёр** — `tools/import_memories.py`. Он читает метаданные, конвертирует файлы и собирает первый черновик книги.
3. **Редактор** — `tools/studio.html`. В нём можно руками исправить группы, порядок, подписи и поставить цензуру.
4. **Финальный сайт** — `index.html`. Именно его будет открывать Соня с флешки.

В интернет ничего не загружается. Обработка происходит локально на Mac.

---

## 1. Подготовить место на диске

Для 800–900 фотографий и 50–70 видео нужен запас свободного места.

Приближённая, не точная оценка:

- исходный экспорт: примерно 15–60 ГБ;
- созданные JPEG, превью и MP4: ещё примерно 10–40 ГБ;
- временный запас во время перекодирования: желательно ещё 10–20 ГБ.

Перед началом разумно иметь **не менее 50 ГБ свободного места**, а при большом количестве длинных 4K-видео — больше.

Не клади исходники сразу на медленную флешку. Сначала делай импорт на внутреннем SSD Mac, а готовый проект копируй на флешку в конце.

---

## 2. Экспортировать материалы из приложения «Фото»

На Mac:

1. Открой приложение **«Фото»**.
2. Выдели нужные фото и видео.
3. В верхнем меню выбери:

   `Файл → Экспортировать → Экспортировать неизменённый оригинал`

4. Экспортируй всё в отдельную папку, например:

   `~/Desktop/Sonya-originals`

Важно выбирать именно **неизменённые оригиналы**. Так лучше сохраняются:

- HEIC;
- исходные даты и время;
- GPS;
- Live Photo как пара изображения и MOV;
- оригинальное качество видео.

После экспорта не переименовывай файлы массово до импорта: одинаковые имена HEIC и MOV помогают связать Live Photos.

---

## 3. Скачать проект

Вариант без Git:

1. Открой репозиторий `decorum-guy/memory-site`.
2. Нажми **Code → Download ZIP**.
3. Распакуй архив.
4. Перемести папку проекта, например, в:

   `~/Desktop/memory-site`

Вариант через Git:

```bash
git clone https://github.com/decorum-guy/memory-site.git
cd memory-site
```

Репозиторий приватный, поэтому GitHub может попросить авторизацию.

---

## 4. Один раз установить инструменты

Открой Terminal и перейди в папку проекта:

```bash
cd ~/Desktop/memory-site
```

Запусти:

```bash
zsh tools/setup_mac.sh
```

Скрипт устанавливает:

- ExifTool — даты, GPS и метаданные Live Photo;
- FFmpeg/FFprobe — совместимые видео и проверка результата;
- Python-окружение;
- Pillow и `pillow-heif` — работа с HEIC.

После установки активируй окружение:

```bash
source .memory-venv/bin/activate
```

Активировать его нужно заново в каждом новом окне Terminal перед запуском импортёра.

---

## 5. Сначала сделать тестовый импорт

Не начинай сразу со всех 900 файлов. Сначала проверь первые 100:

```bash
python3 tools/import_memories.py \
  "$HOME/Desktop/Sonya-originals" \
  --limit 100
```

После завершения появятся:

- `content/memories.js` — структура книги;
- `content/import-report.json` — отчёт импорта;
- `media/generated/photos/` — совместимые JPEG;
- `media/generated/thumbs/` — лёгкие превью;
- `media/generated/videos/` — обычные видео H.264/AAC;
- `media/generated/posters/` — обложки видео;
- `media/generated/live/` — видеочасти Live Photos.

Открой `content/import-report.json` и проверь поле `errors`.

Если `errors` пустой, тест прошёл нормально.

Если там есть ошибки, в каждой записи будет путь к проблемному файлу и сообщение FFmpeg.

---

## 6. Проверить тест в Memory Studio

Открой:

```bash
open tools/studio.html
```

В Studio проверь:

- даты выглядят правдоподобно;
- фото одного дня в основном находятся рядом;
- видео имеют постеры и пометку длительности;
- Live Photos помечены `LIVE`;
- картинки отображаются, а не показывают битые ссылки.

Автоматическая группировка — только черновик. Средний цвет и perceptual hash могут ошибаться, поэтому ручная корректировка предусмотрена специально.

---

## 7. Запустить полный импорт

После успешного теста:

```bash
python3 tools/import_memories.py \
  "$HOME/Desktop/Sonya-originals"
```

Импортёр не обрезает обычные видео по длительности. Ролик на 10 минут будет обработан целиком.

По умолчанию видео приводятся к:

- MP4;
- H.264;
- AAC;
- максимум 1920 пикселей по ширине;
- `faststart` для быстрого начала воспроизведения;
- совместимой цветовой разрядности `yuv420p`.

Длинные и 4K-видео могут обрабатываться заметно дольше фотографий. Это нормально.

### Управление качеством видео

Стандартный режим:

```bash
python3 tools/import_memories.py "$HOME/Desktop/Sonya-originals"
```

Быстрее и немного тяжелее по размеру:

```bash
python3 tools/import_memories.py \
  "$HOME/Desktop/Sonya-originals" \
  --video-preset ultrafast
```

Меньше размер, но дольше обработка:

```bash
python3 tools/import_memories.py \
  "$HOME/Desktop/Sonya-originals" \
  --video-preset medium \
  --video-crf 24
```

Не ставь CRF выше 27 без проверки качества. Меньшее значение означает лучшее качество и больший файл.

### Управление группировкой

Стандартные параметры:

- обычный разрыв события: 75 минут;
- расширенный разрыв: 180 минут;
- визуальный порог: 0.72.

Пример более строгой группировки:

```bash
python3 tools/import_memories.py \
  "$HOME/Desktop/Sonya-originals" \
  --gap-minutes 55 \
  --merge-gap-minutes 130 \
  --visual-threshold 0.78
```

Чем выше `visual-threshold`, тем реже визуально похожие фото объединяются автоматически.

## 8. Проверить отчёт после полного импорта

Открой:

`content/import-report.json`

Проверь:

- `foundFiles` — сколько исходных файлов найдено;
- `importedItems` — сколько элементов попало в книгу;
- `events` — сколько событий создано;
- `errors` — что не удалось обработать.

Live Photo состоит из двух файлов, но в книге считается одним элементом. Поэтому `foundFiles` и `importedItems` не обязаны совпадать.

Если импортёр завершился с кодом `1`, это означает, что книга создана, но некоторые видео или видеочасти Live Photo не обработались. Их список находится в `errors`.

---

## 9. Исправить события вручную

Открой:

```bash
open tools/studio.html
```

В Studio можно:

- перетаскивать фото и видео из одного события в другое;
- менять порядок файлов внутри события;
- менять порядок событий;
- объединять событие с предыдущим;
- создавать новые события;
- удалять материалы из книги, не удаляя файлы с диска;
- менять название и общую подпись события;
- менять подпись каждого фото или видео;
- помечать отдельные файлы цензурой;
- отменять последние действия;
- сохранять черновик в браузере.

### Как поставить цензуру

У каждой карточки есть кнопка **«Скрыть»**.

После нажатия:

- карточка размывается в Studio;
- в данных файла появляется `"censored": true`;
- в финальной книге изображение или постер будут полностью размыты;
- при открытии появится предупреждение: «Содержание может быть шокирующим»;
- фото или видео откроется только после кнопки **«Показать»**;
- цензурированное видео не подставляется в плеер до подтверждения.

Чтобы снять цензуру, нажми кнопку **«Скрыто»** ещё раз.

### Как не потерять работу

Периодически нажимай **«Сохранить черновик»**.

Это сохранение хранится только в текущем браузере на текущем Mac. Оно не заменяет экспорт файла.

После большой серии правок нажимай **«Экспортировать memories.js»** и сохраняй отдельную копию.

## 10. Экспортировать правки из Studio

Когда группировка и подписи готовы:

1. Нажми **«Экспортировать memories.js»**.
2. Браузер скачает новый файл `memories.js`.
3. Замени им файл:

   `content/memories.js`

4. Открой `index.html` и проверь результат.

Не перемещай отдельно папки `media/generated`: пути в `memories.js` рассчитаны относительно корня проекта.

## 11. Отредактировать обложку и общие тексты

В начале `content/memories.js` находится объект `meta`:

```js
"meta": {
  "eyebrow": "Личная книга воспоминаний",
  "title": "Наши три года",
  "subtitle": "Не идеальные. Настоящие.",
  "note": "Сначала собраны автоматически. Потом — поправлены вручную.",
  "footer": "Спасибо за всё, что было между первой и последней страницей.",
  "accent": "#9c3f43"
}
```

Его можно изменить вручную в текстовом редакторе.

После ручного редактирования не удаляй:

- кавычки;
- запятые;
- фигурные скобки;
- строку `window.MEMORY_BOOK =`;
- точку с запятой в самом конце файла.

## 12. Проверить финальный сайт

Открой:

```bash
open index.html
```

Обязательно проверь:

1. Обложка открывается.
2. Все главы доступны.
3. Миниатюры не битые.
4. Случайные 20–30 фотографий открываются крупно.
5. Несколько Live Photos оживают по кнопке.
6. Короткое видео воспроизводится со звуком.
7. Самое длинное видео запускается, перематывается и доигрывает до конца.
8. Вертикальное и горизонтальное видео имеют правильную ориентацию.
9. Цензурированное фото не видно до кнопки «Показать».
10. Цензурированное видео не начинает загружаться или играть до подтверждения.
11. Стрелки галереи и Escape работают.
12. Сайт нормально выглядит при узком окне.

После проверки закрой сайт, отключи интернет и открой `index.html` ещё раз. Всё должно работать офлайн.

## 13. Подготовить флешку

1. Отформатируй флешку в `exFAT`.
2. Скопируй на неё **всю папку проекта целиком**.
3. При желании переименуй `index.html` в `ОТКРОЙ_МЕНЯ.html`.
4. Остальные файлы и папки не переименовывай.
5. Рядом можно положить папку `ORIGINALS` с исходными материалами как резервный архив.

Рекомендуемая структура:

```text
MEMORY/
├── ОТКРОЙ_МЕНЯ.html
├── assets/
├── content/
├── media/
├── tools/
├── HOW_TO_START.md
└── ORIGINALS/        необязательно
```

`tools/` можно оставить на флешке: Соня не попадёт туда случайно. Но при желании после завершения можно убрать `tools/`, `.memory-venv`, `.git` и резервные `memories.backup-*.js`, чтобы уменьшить размер.

Не удаляй:

- `assets/`;
- `content/memories.js`;
- `media/generated/`.

---

## 14. Финальная проверка именно с флешки

Нельзя считать проект готовым только потому, что он работает с SSD Mac.

Проверь файл непосредственно на флешке:

- в Safari на Mac;
- в Chrome или Edge;
- по возможности на Windows;
- без интернета.

Особенно проверь самое длинное видео. Скорость дешёвой флешки может быть узким местом даже при исправном сайте.

Если длинное видео тормозит именно с флешки, это может быть ограничение скорости накопителя, а не кода. В таком случае нужна более быстрая USB 3.x флешка.

---

## 15. Что не нужно делать

- Не открывай HEIC напрямую в финальном сайте — для этого создаются JPEG-копии.
- Не клади в `memories.js` абсолютные пути вида `/Users/artem/...`.
- Не запускай повторный полный импорт после ручной работы без резервной копии: импортёр заменяет `content/memories.js`, но предварительно создаёт timestamp-бэкап.
- Не редактируй сгенерированные имена файлов вручную без одновременной правки путей.
- Не считай автоматическую группировку точной классификацией событий.
- Не отдавай флешку без проверки самого длинного ролика и цензуры.

## 16. Короткий сценарий на два дня

### Первый день

1. Экспортировать оригиналы из Фото.
2. Установить инструменты.
3. Сделать тест на 100 файлах.
4. Запустить полный импорт.
5. Пока кодируются видео, подготовить названия ключевых событий и подписи.

### Второй день

1. Проверить `import-report.json`.
2. Исправить основные ошибки группировки в Studio.
3. Удалить мусор и дубли из книги.
4. Поставить цензуру.
5. Написать подписи к ключевым событиям.
6. Экспортировать `memories.js`.
7. Проверить сайт офлайн.
8. Скопировать на флешку.
9. Повторно проверить уже с флешки.

Не нужно вручную подписывать все 900 файлов. Разумнее дать человеческие подписи ключевым событиям и отдельным важным кадрам, а на остальных оставить автоматически созданные дату и время.
