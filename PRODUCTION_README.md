# Production-версия Memory Site

Эта инструкция описывает финальный путь: загрузить весь архив фото, видео и Live Photos, отредактировать книгу, надёжно сохранить изменения и собрать чистую офлайн-версию на флешке.

> **Главное правило:** `.memory-test` — одноразовая тестовая копия. Ничего, что отредактировано внутри `.memory-test/site`, автоматически не переносится в production. Финальную книгу нужно импортировать и редактировать из корня основного проекта `memory-site`.

---

## 1. Что должно получиться в конце

Для работы готовой книги нужны только:

```text
index.html
assets/
content/
media/
```

Сайт остаётся полностью статическим. Домен, сервер, аккаунт и интернет ему не нужны. Исключение — переход по ссылке Shared Album, если этот дополнительный блок включён.

Рабочий проект на Mac лучше сохранить отдельно: в нём остаются Studio, импортёр, резервные копии и возможность позднее внести изменения.

---

## 2. Подготовка исходных фото, видео и Live Photos

### Экспорт из приложения «Фото» на Mac

Для архива из медиатеки Apple используй:

```text
Фото → Файл → Экспортировать → Экспортировать неизменённые оригиналы
```

Это важно, потому что такой экспорт лучше сохраняет:

- исходные даты и metadata;
- HEIC/HEIF вместо повторно сжатых копий;
- оригинальные MOV/MP4;
- пару изображение + MOV у Live Photo;
- Apple ContentIdentifier, когда он присутствует.

Для Live Photo в исходной папке обычно лежат два файла: фотография и короткое видео. Не удаляй MOV и не переименовывай две половины пары по-разному.

Импортёр рекурсивно просматривает вложенные папки, поэтому исходники можно раскладывать по годам или альбомам. Поддерживаются:

```text
Фото:  HEIC, HEIF, JPG, JPEG, PNG, WEBP, TIF, TIFF
Видео: MOV, MP4, M4V
```

Исходную папку держи **вне репозитория**. Например:

```text
~/Desktop/SONYA_ORIGINALS/
```

Не удаляй её до окончания всех проверок и копирования флешки.

## 3. Один раз установить инструменты

Из корня проекта:

```bash
cd ~/Desktop/memory-site
zsh tools/setup_mac.sh
source .memory-venv/bin/activate
```

Скрипт устанавливает или настраивает Python 3.12, ExifTool, FFmpeg и Python-зависимости проекта.

В новом окне Terminal окружение нужно активировать повторно:

```bash
cd ~/Desktop/memory-site
source .memory-venv/bin/activate
```

## 4. Сначала проверить весь архив без записи

Укажи реальный путь к папке исходников:

```bash
SOURCE="$HOME/Desktop/SONYA_ORIGINALS"
python3 tools/import_workflow.py dry-run "$SOURCE"
```

Dry run ничего не меняет в книге. Он проверяет:

- читаются ли изображения;
- открываются ли видео через FFmpeg/FFprobe;
- сколько файлов имеют точную дату;
- сколько файлов имеют GPS;
- сколько Live Photo пар найдено;
- хватает ли места на диске;
- какие файлы будут проигнорированы.

Число найденных Live Photo пар должно быть разумно похоже на количество подготовленных Live Photos. Совпадение может быть не абсолютно точным: старые или повторно экспортированные файлы иногда теряют Apple ContentIdentifier, и тогда импортёр сопоставляет пару по имени и времени.

---

## 5. Необязательная репетиция на тестовой копии

Для быстрой проверки первых 100 файлов:

```bash
python3 tools/import_workflow.py reset test --yes
python3 tools/import_workflow.py test "$SOURCE" --limit 100 --open
```

Полная тестовая репетиция:

```bash
python3 tools/import_workflow.py reset test --yes
python3 tools/import_workflow.py test "$SOURCE" --open
```

Она создаёт изолированную копию:

```text
.memory-test/site/
```

Тест не меняет production. После оценки тестовую область можно удалить:

```bash
python3 tools/import_workflow.py reset test --yes
```

## 6. Полный production-импорт

После успешного dry run:

```bash
python3 tools/import_workflow.py import "$SOURCE"
```

Без `--yes` скрипт попросит подтверждение перед записью. Для финального импорта это безопаснее, чем безусловный запуск.

Production-импорт создаёт или обновляет:

```text
content/memories.js
content/import-report.json
media/generated/photos/
media/generated/thumbs/
media/generated/videos/
media/generated/live/
media/generated/posters/
```

Импортёр также сохраняет резервную копию предыдущего `content/memories.js`.

### Важное предупреждение

Повторный полный импорт следует считать **пересборкой структуры книги**. Если после импорта ты уже вручную переставил события, изменил подписи, кадрирование и обложку, новый импорт может заменить эту структуру автоматически созданной версией. Поэтому рекомендуемый порядок такой:

```text
полный импорт → ручная редактура → применение memories.js → сборка флешки
```

## 7. Запустить единую Studio для production

Запускай сервер именно из корня основного проекта:

```bash
cd ~/Desktop/memory-site
source .memory-venv/bin/activate
python3 tools/telegram_server.py
```

Не используй для финальной версии команду с `.memory-test/site`.

Откроется локальная Studio. В верхней части есть две вкладки:

```text
Memory Studio | Telegram Studio
```

Один сервер обслуживает обе Studio и предпросмотр книги.

Адреса:

```text
http://127.0.0.1:8765/tools/studio.html
http://127.0.0.1:8765/tools/telegram_studio.html
http://127.0.0.1:8765/index.html?opened=1
```

Для остановки сервера нажми в Terminal:

```text
Ctrl+C
```

## 8. Как сохранять изменения в Memory Studio

Memory Studio редактирует структуру основной книги:

- группы и порядок событий;
- расположение фото и видео;
- подписи;
- цензуру;
- кадрирование;
- выбранный кадр обычного видео;
- обложку и финальную подпись;
- названия, годы и пояснения глав.

### Черновик и финальное сохранение — не одно и то же

Черновик Studio хранится локально в браузере. Он помогает продолжить работу, но сам по себе **не является production-файлом книги**.

После завершения очередного большого этапа:

1. Нажми в Memory Studio **«Экспортировать memories.js»**.
2. Браузер скачает файл, обычно в `~/Downloads/memories.js`.
3. Примени его к production командой:

```bash
python3 tools/studio_workflow.py apply production "$HOME/Downloads/memories.js" --open
```

Если браузер назвал файл `memories (1).js`, укажи его фактическое имя:

```bash
python3 tools/studio_workflow.py apply production "$HOME/Downloads/memories (1).js" --open
```

Команда:

- проверяет структуру экспортированного файла;
- проверяет, что все указанные медиа существуют;
- создаёт резервную копию текущего `content/memories.js`;
- заменяет production-файл;
- повторно проверяет его после записи;
- при ошибке восстанавливает предыдущую версию.

Резервные копии выглядят примерно так:

```text
content/memories.before-studio-YYYYMMDD-HHMMSS.js
```

После успешного применения скачанный файл в `Downloads` больше не является единственной копией: актуальная версия находится в `content/memories.js`.

### Практический ритм сохранения

Не жди окончания всей многочасовой редакции. После каждого крупного этапа:

```text
экспортировать memories.js → применить production → проверить книгу
```

## 9. Как сохраняется Telegram-глава

Во вкладке Telegram Studio кнопка **«Сохранить главу»** записывает изменения непосредственно в production-проект:

```text
content/telegram-data.json
content/telegram.js
media/telegram/
```

Отдельный экспорт для Telegram не требуется.

После сохранения открой предпросмотр и проверь записки, цитаты, скриншоты и их расположение.

Чтобы Telegram-глава показывалась в готовой книге постоянно, в `content/settings.js` должно быть:

```js
telegramEnabled: true,
```

При `false` глава сохранена, но скрыта из книги и навигации.

## 10. Shared Album — необязательно

Создать QR, записать ссылку и включить карточку:

```bash
python3 tools/generate_shared_album_qr.py "ССЫЛКА_НА_SHARED_ALBUM"
```

Команда обновляет `content/settings.js` и создаёт:

```text
media/shared-album-qr.png
```

Сама книга и QR работают офлайн, но переход по ссылке Shared Album требует интернет.

## 11. Финальные настройки

Перед сборкой флешки проверь `content/settings.js`:

```js
window.MEMORY_SETTINGS = {
  telegramEnabled: true,          // если Telegram-глава нужна
  sharedAlbumEnabled: false,      // true, если Shared Album настроен
  sharedAlbumUrl: "",
  sharedAlbumQr: "media/shared-album-qr.png",
  censorshipEnabledByDefault: true,
  readerControlsEnabled: true
};
```

Не копируй этот пример целиком поверх файла, если Shared Album уже настроен: проверь именно фактические значения в существующем `content/settings.js`.

## 12. Проверка production перед флешкой

Запусти production-сервер:

```bash
python3 tools/telegram_server.py
```

Проверь минимум:

- обложку и кнопку открытия;
- порядок и названия глав;
- начало, середину и конец книги;
- несколько обычных фотографий;
- несколько длинных видео;
- несколько Live Photos со звуком;
- ручной mute/unmute;
- подписи и кадрирование;
- скрытые материалы и переключатель цензуры;
- Telegram-главу;
- Shared Album и QR, если они включены;
- отсутствие пропавших картинок и пустых карточек.

После этого останови сервер и отдельно открой двойным кликом сам `index.html`. Финальная флешка будет работать через `file://`, поэтому нужно проверить именно этот сценарий, а не только localhost.

Также полезно отключить интернет и повторить проверку. Всё, кроме внешней ссылки Shared Album, должно продолжить работать.

## 13. Собрать чистую production-папку

Не копируй на подарочную флешку рабочий репозиторий целиком. В нём есть Git, тесты, Studio, Python-окружение и служебные файлы.

Создай чистую папку на рабочем столе:

```bash
cd ~/Desktop/memory-site
DEST="$HOME/Desktop/SONYA_MEMORY_PRODUCTION"
rm -rf "$DEST"
mkdir -p "$DEST"

cp index.html "$DEST/index.html"
ditto assets "$DEST/assets"
ditto content "$DEST/content"
ditto media "$DEST/media"
```

Эти четыре элемента содержат всё, что нужно готовому сайту.

### Необязательная папка с оригиналами

Оригиналы не нужны для работы книги, но их можно положить рядом как отдельный архив, если на флешке хватает места:

```bash
mkdir -p "$DEST/ORIGINALS"
ditto "$SOURCE" "$DEST/ORIGINALS"
```

Не помещай оригиналы внутрь `media/`: сайт их не использует, а структура станет тяжелее и запутаннее.

### Удалить служебные файлы macOS

Перед копированием на флешку:

```bash
find "$DEST" -name ".DS_Store" -delete
find "$DEST" -name "._*" -delete
```

## 14. Можно ли переименовать финальный HTML

**Да.** В `index.html` используются относительные пути к `assets`, `content` и `media`, поэтому копия HTML под другим именем продолжает работать, пока она лежит в той же корневой папке.

Но инструменты разработки и предпросмотр ожидают именно имя `index.html`. Поэтому безопаснее:

1. В рабочем проекте оставить `index.html` без изменений.
2. В готовой production-папке создать красивую копию:

```bash
cp "$DEST/index.html" "$DEST/ОТКРОЙ МЕНЯ.html"
```

На флешке останутся оба файла:

```text
ОТКРОЙ МЕНЯ.html   ← красивый файл для получателя
index.html         ← стандартный и максимально совместимый запасной вход
assets/
content/
media/
```

Современные macOS и Windows обычно нормально открывают имена с кириллицей и пробелами. `index.html` всё равно лучше сохранить как резервный вариант.

Не перемещай `ОТКРОЙ МЕНЯ.html` в отдельную папку: тогда относительные пути перестанут указывать на соседние `assets`, `content` и `media`.

Не используй в имени символы, запрещённые Windows, например:

```text
< > : " / \ | ? *
```

## 15. Оформление production-флешки

### Формат

Для совместимости с macOS и Windows используй **exFAT**. Форматирование удаляет всё с накопителя, поэтому сначала убедись, что на нём нет нужных файлов.

В macOS:

```text
Дисковая утилита → выбрать флешку → Стереть → exFAT
```

### Рекомендуемая структура

```text
ФЛЕШКА/
├── ОТКРОЙ МЕНЯ.html
├── index.html
├── assets/
├── content/
├── media/
└── ORIGINALS/              # необязательно
```

Можно добавить обычный текстовый файл `README.txt` с одной строкой:

```text
Открой файл «ОТКРОЙ МЕНЯ.html» в Safari, Chrome или Яндекс Браузере.
```

### После копирования

1. Извлеки флешку безопасно.
2. Подключи её снова.
3. Открой `ОТКРОЙ МЕНЯ.html` именно с флешки.
4. Проверь несколько фото, видео и Live Photos.
5. Проверь книгу без интернета.
6. При возможности проверь флешку ещё на одном компьютере.

Не удаляй рабочую production-папку с Mac сразу после вручения. Флешка не должна быть единственной копией готовой книги.
